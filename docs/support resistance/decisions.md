## [2026-05-19] Cascade 選線架構：三層 → 兩層

- **內容：** 將三層機制（Tier 1 / Tier 2 / Tier 3）簡化為兩層（主要邏輯 + 保底）
- **選項對比：** A) 保留三層（含 Tier 2 放寬含括率）/ B) 移除 Tier 2，直接保底
- **理由：** 所有候選組合含括率均超過 70%，Tier 2 在實際資料中從不觸發，屬於死碼；去除後邏輯更清晰
- **風險：** 若未來新增含括率低於 70% 的候選，需重新考慮是否恢復中間層
- **影響：** `MANUAL.md`、`SR_SELECTION_LOGIC.md`、`ManualPage.tsx`（§4-1 選線策略）

## [2026-05-19] 保底錨定對統一為 N日最低＋N日最高

- **內容：** 三期別保底均改為 N日最低＋N日最高（短期 10日、中期 20日、長期 240日），三種趨勢共用同一組
- **選項對比：** A) 沿用舊設計（多頭 MA20＋20日最高、空頭 20日最低＋MA20 等）/ B) 統一用 N日高低
- **理由：** N日最高 ≥ N日最低為數學定義保證，R > S 必然成立；舊設計在極端行情下 MA 可能突破高低點導致 R ≤ S；新設計無條件輸出，不依賴趨勢或 VP
- **風險：** 保底區間較寬，視覺上比主要邏輯的候選對更大；屬低頻觸發，影響有限
- **影響：** `MANUAL.md`（§4-2 各表下方 note + §4-3）、`SR_SELECTION_LOGIC.md`（LAST_RESORT dict）、`ManualPage.tsx`（§4-3 表格）

## [2026-05-19] 中期候選清單去重

- **內容：** 移除 mid.bull / mid.bear / mid.sideways 候選中因不同 VP 視窗重複出現的同一指標組合，只保留含括率較高的一組
- **選項對比：** A) 保留全部（含重複）/ B) 依去重原則只保留最高含括率
- **理由：** 重複列在 Cascade 中實際上只有第一次命中有意義，後續列永遠不會被執行，保留只增加混淆
- **風險：** 無。去重後 mid.bull 8列、mid.bear 8列、mid.sideways 4列，與 MANUAL.md 完全對齊
- **影響：** `MANUAL.md`（§4-2 中期各表）、`ManualPage.tsx`（CANDIDATES 資料）

## [2026-04-29] SR 選層邏輯

- **內容：** 直接使用 `cache_layers_selected.json` 的 L1→L2→L3 結果，不重新計算
- **選項對比：** A) 最高命中率指標優先 / B) 價位 clustering / C) 使用現有 pipeline 結果
- **理由：** 後端 pipeline 已完成選層，L1 是最高質量 VP 關卡，直接復用避免重複計算
- **風險：** 若 pipeline 選層邏輯有 bug，前端會直接呈現錯誤；目前無獨立驗證機制
- **影響：** `08_generate_sr_summary.py`、`SRSummaryPanel.tsx`

## [2026-04-29] 描述文字格式

- **內容：** 採用技術標籤（"5日VAL"、"MA20"、"上關"），不使用自然語言
- **選項對比：** A) 技術標籤 / B) AI 自然語言 / C) 兩者皆有
- **理由：** 目標用戶是有經驗的交易者，技術標籤直接傳遞信息；自然語言需要更多 context 目前後端未計算
- **風險：** 初次使用者可能不熟悉縮寫；日後可在同一 JSON 欄位加 summary 文字
- **影響：** `SRSummaryPanel.tsx` 的 label 顯示

## [2026-04-29] 展開內容範圍

- **內容：** 顯示所有同期指標 + 命中率 + 距現價%
- **選項對比：** A) 全部指標 / B) 只顯示 ±0.5% 內的指標 / C) 全部指標含命中率和距現價%
- **理由：** 使用情境是收盤覆盤，使用者需要完整判斷依據；方案 B 在現價遠離 SR 時顯示空白，體驗差
- **風險：** 指標列表較長（約 10-12 筆），但不需虛擬化
- **影響：** `SRSummaryPanel.tsx` IndicatorTable

## [2026-04-29] 使用情境定義

- **內容：** 以收盤後覆盤為主要使用情境，不支援盤中即時更新
- **選項對比：** 盤前規劃 / 盤中即時 / 收盤覆盤
- **理由：** 使用者明確指定；盤中即時需要 tick 級資料，成本高 10 倍
- **風險：** 未來若需要盤中即時功能，需重新設計資料管線
- **影響：** 整體資料更新頻率設計（目前每日收盤後執行一次腳本）
