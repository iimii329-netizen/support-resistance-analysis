# 為何不需要分產業選線

**日期：** 2026-05-12  
**資料來源：** `OUTPUT/csv/sr_zone_rank_full.csv`（34 產業 × 3 趨勢 × 3 期別回測結果）

---

## 一、Cascade 機制是什麼

Cascade（瀑布式遞補）是本系統的核心選線機制。

**概念：** 不預設「一定要用哪個指標」，而是準備一份**按優先順序排好的候選清單**，從第一個開始試，通過驗證就用，不通過就繼續試下一個，直到找到第一個有效組合為止。

```
候選清單（按優先順序）：
  #1  cdp_nl + cdp_nh     → 驗證：R > S？min_width？→ 通過 → 採用，停止
  #2  lower_gate + cdp_nh → 驗證（若 #1 失效才到這）
  #3  cdp_nl + upper_gate → 驗證（若 #1、#2 均失效才到這）
  ...
  #N  last resort 錨定對  → 只查 R > S，幾乎必然通過
```

**為什麼這樣設計：**  
每支股票每天的狀態不同，固定用同一個指標會有失效的風險（例如 CDP 在跳空時失效、VP 資料缺失時 vol_dense 無法計算）。Cascade 讓系統自動找到當天當股「第一個有效的選擇」，不需要人工判斷例外。

**三個層級：**

| 層級 | 觸發條件 | 含括率門檻 | 額外限制 |
|------|---------|-----------|---------|
| Tier 1 | 正常情況 | > 70% | 長期寬度 ≤ 40% |
| Tier 2 | Tier 1 全失效 | 不設門檻 | 僅保留 min_width |
| Tier 3 | Tier 2 全失效 | 不設門檻 | 只查 R > S |

## 二、為何不需要分產業

### 證據一：頂部候選跨產業完全重疊

分析各 period/trend 的候選組合出現在幾個產業中（`n_industries`）：

| 期別/趨勢 | 前幾名候選 | 覆蓋產業數 |
|----------|-----------|---------|
| 短期（全趨勢） | cdp_nl + cdp_nh、cdp_al + cdp_ah、lower_gate + cdp_nh | **34 / 34** |
| 中期 / 多頭 | ma20 + vol_dense_upper、vol_dense_lower + vol_dense_upper | **34 / 34** |
| 中期 / 空頭 | vol_dense_lower + ma20、vol_dense_lower + vp20_vah | **34 / 34** |
| 長期 / 多頭 | ma60 + high_240d、ma120 + high_240d | **34 / 34** |
| 長期 / 空頭 | low_240d + ma60、low_240d + vp60_vah | **34 / 34** |

34 個產業使用的是**完全相同的指標池**，光電業和金融業的候選清單看不出差異。

---

### 證據二：產業差異只影響排名，不影響指標池

各產業 rank=1 的結果呈現輕微分歧，但都在同一個指標池裡：

| 產業（範例） | 短期 / 空頭 rank=1 | 中期 / 多頭 rank=1 |
|------------|------------------|------------------|
| 光電業 | cdp_nl + cdp_nh | ma20 + vol_dense_upper |
| 機電業 | cdp_nl + cdp_nh | ma20 + vol_dense_upper |
| 電子零組件 | cdp_al + cdp_ah | ma20 + vol_dense_upper |
| 運動休閒 | lower_gate + cdp_nh | vp20_val + vol_dense_upper |
| 紡織 | cdp_al + cdp_ah | ma20 + vol_dense_upper |

差異點是：某些產業的 rank=1 是 `cdp_al + cdp_ah`，其他是 `cdp_nl + cdp_nh`。  
**但這兩個都已經在通用候選清單的前 9 個裡面。**

---

### 證據三：Cascade 本身就是軟性的產業適配

以短期為例，用戶 A（光電業）和用戶 B（電子零組件）使用同一份通用候選清單：

```
通用 Tier 1 候選清單（短期）：
  #1  cdp_nl + cdp_nh    ← 光電業的 rank=1，含括率 99.97%，正常日必過
  #2  lower_gate + cdp_nh
  #3  cdp_nl + upper_gate
  ...
  #9  cdp_al + cdp_ah    ← 電子零組件的 rank=1，若前面都沒過才到這
```

正常交易日，兩支股票都在 #1 就找到有效組合（含括率 99.97%）。  
若某天電子零組件的走勢讓 `cdp_nl + cdp_nh` 失效，Cascade 繼續往下，最終選到歷史上最適合它的那個組合。

**結果等同於分產業，但不需要維護 34 張 lookup table。**

---

### 三、什麼情況下分產業才真正有必要

| 條件 | 現況 |
|------|------|
| 某產業有獨特指標，不在通用候選池裡 | 不存在，34 個產業使用相同指標池 |
| 某產業特定指標含括率低於 70%，其他產業高於 70% | 可能存在邊緣案例，由 Tier 2 / Tier 3 自動接手 |
| 需要「第一個候選就命中」，不允許 Cascade 往下找 | 若有極高精準度需求（如機器交易），才值得做 per-industry lookup |

---

## 三、結論

不分產業的核心理由：

1. **指標池相同**：34 個產業的最佳候選都在同一個指標池裡，沒有產業專屬指標
2. **Cascade 涵蓋排名差異**：產業間只差「哪個排第一」，Cascade 機制會自動找到通過驗證的那個
3. **工程成本不對等**：分產業只能讓第一個候選命中率從 ~97% 升至 ~99%，卻要維護 34 張 lookup table
4. **彈性更好**：通用邏輯可自動適應新上市股票、產業重新分類、指標資料缺失等情況，per-industry 表格需要手動更新

若未來某個產業出現明顯例外（例如某類股 CDP 失效率特別高），再針對該產業加入例外規則即可，不需要一開始就全面分產業。
